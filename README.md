# 一笔

一个只属于自己的记账应用。Rust 服务、SQLite 数据库、内嵌静态前端，面向同时运行其他服务的 2 核 / 2GB 云服务器。

## 已确认的需求

- 单人账本，用户名和密码登录，不开放注册。
- 从 2026 年 7 月起正式记账；允许手动补录少量旧会员。
- 导入微信、支付宝账单，先预览，再确认入账；重复导入不能重复记账。
- 自动分类、手动纠正、商户分类规则。
- 同时记录支出、实发工资和单独的年终奖；账户间转账不计收入。
- 付款日期与费用所属月份分开：148 元会员可从 2027 年 2 月起连续分摊 12 个月。
- 金额以整数分保存；分摊总额必须与原始金额严格相等。
- 提供现金收支与按月分摊两个统计口径；历史缺失月份不当作零收入。
- 响应式中文前端，柔和渐变和适量毛玻璃。
- Git 按可验证的小步骤提交，避免把全部功能堆成一次提交。

## 实现原则

一个服务进程和一个数据库文件，不依赖常驻 Node.js、Redis、外部数据库或本地大模型。前端由 Rust 服务提供，部署时接入已有 HTTPS 反向代理。真实账单、数据库、密码和运行日志不进入 Git。

## 本地运行

需要 Rust 1.98 或更新版本、C 编译器。SQLite 随二进制编译，前端无需 Node.js 或构建工具。

```sh
cargo build --locked
./target/debug/tally init 你的用户名
./target/debug/tally serve --dev
```

在浏览器打开 `http://127.0.0.1:3080`。初始化时交互输入至少 12 个字符的密码；没有默认账户或默认密码。再次运行 `init` 会重置用户名和密码并撤销全部旧会话。

`--dev` 使用适合本机 HTTP 的 Cookie，且只允许监听回环地址。线上使用 `tally serve` 并通过 HTTPS 反向代理访问。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `TALLY_DB` | `data/tally.sqlite3` | 数据库位置 |
| `TALLY_BIND` | `127.0.0.1:3080` | 服务监听地址 |

## 使用方式

- **记一笔**：选择支出、收入、账户转账或退款；支持补录早于记账起点的记录。
- **会员分摊**：选“按月分摊”，填写费用开始月份和 2–120 个月期限。按自然月分摊，开始月份计第一期；不按天折算。结束月份自动计算。
- **工资与奖金**：每月填写实际到账金额。工资模板复制最近一次信息，保存前确认金额和日期；年终奖使用独立分类。
- **导入账单**：支持微信/支付宝的 CSV、GBK CSV、XLSX 明细。ZIP 下载包须先解压。预览后勾选确认；重复项不能再次入账，早于正式记账起点的明细默认不选。
- **分类规则**：内置关键词分类，无法判断时归入“待分类”。修改流水时可保存商户规则；自定义规则优先用于今后的导入，不会改写历史记录。
- **两个统计口径**：“净收支”按原交易月份统计退款后的净额；“按月分摊”把跨月净支出计入原服务期限。账户间转账不算收入或费用。
- **退款**：原付款和退款流水都保留。全额退款的支出、独立退款行在列表显示留档标识，原始金额仍可在编辑中查看；部分退款只计剩余净额。跨月退款回冲原支出月份，不作为退款月份的收入或负支出。
- **退款确认与关联**：导入时读取原支出的“已全额退款”或明确的累计已退款金额。没有可靠原交易号的独立退款仅留档；可编辑它并手动关联原支出，或在原支出上填累计已退款金额。已确认累计额与关联退款合计取较大值，避免同一笔退款重复抵扣；不是把两者相加。未知、处理中或超额的退款状态会提示核对。
- **退款后的分摊**：净额按原开始月份和期限重新精确分配；全退后费用和未来待分摊均为零，记录仍可查。如服务期限也改变，可另外编辑分摊期限。
- **退款状态更新**：重新导入相同交易时，若累计退款增加，预览允许确认更新原记录，保留你已修改的分类、备注和分摊；不会新增一笔付款。
- **收入平均值**：以正式起点至所选月份中，有收入记录的月份为分母，可以切换是否包含年终奖；不把缺失月份视为零收入。
- **导出**：设置页下载标准 JSON，含流水和分类规则，不包含密码哈希或登录会话。完整恢复使用数据库备份。

这是一套收支和费用账本，不计算银行卡真实余额、税额或投资收益。账户字段用于区分支付渠道，没有期初余额对账功能。

## 安全与资源

- 单人账户；Argon2 密码哈希；随机会话令牌在数据库中只存 SHA-256；会话有效期 7 天。
- Cookie 使用 HttpOnly、SameSite=Strict，生产模式启用 Secure。写接口要求自定义请求头，未开启跨域访问；所有数据、导出和导入接口均要求登录。
- 每分钟最多 8 次登录尝试；同一时间只验证一个密码、解析一份账单。运行时为 2 个异步工作线程，最多 4 个阻塞工作线程。
- 上传文件最大 8MiB、每次最多 10,000 笔；XLSX 解压总量不超过 32MiB，解析前检查单元格范围，避免稀疏大表耗尽内存。
- 原始上传文件不落盘。规范化预览写入数据库，逻辑有效期 30 分钟，导入后删除；再次上传会替换旧预览。过期但未再次访问的预览可能留在数据库中，完整备份包含数据库内容。
- SQLite WAL 模式，默认 2MiB 页缓存。数据库文件创建时权限为 `0600`；部署服务使用 `UMask=0077`。
- 当前开发环境的静态发布版小样本 HTTP 验收中，进程常驻约 5MiB、峰值约 24MiB。该数值不是生产上限，导入更大账单时会增加。

## 验证

```sh
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --locked
python3 scripts/smoke.py
```

冒烟脚本使用临时数据库并自动结束测试服务，覆盖真实登录、收入、分摊、CSV/XLSX、重复导入、导出及一致性备份。`scripts/browser-smoke.cjs` 是可选的 Playwright 验收脚本，**仅用于一次性的演示数据库**；通过 `TALLY_BROWSER_CONFIG` 指定含 `base`、`username`、`password` 的本地测试配置，使用 `TALLY_BROWSER_CHANNEL=msedge` 可调用现有 Edge。

已使用用户提供的真实微信 XLSX 在本机验证：190 笔、0 解析错误；包含 Excel 数字日期和退款状态。真实文件、流水内容及临时数据库不进入 Git 或部署包。支付宝使用合成的典型导出格式验收。

退款更新已通过 20 项 Rust 测试、112 项静态发布版 HTTP 检查和 12 项桌面/手机退款浏览器流程；格式检查和 Clippy 无警告。浏览器验收使用独立的合成账本，脚本见 `scripts/`。

部署和备份见 [部署说明](docs/deployment.md)。
